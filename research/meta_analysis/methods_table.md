## Gemma 4 E2B facts used in the applicability column

Provenance tags: **[code]** = from the `modeling_gemma4.py`/`config.json` reading by LIT-03 (LIT03-004, LIT03-005, `LIT03 §4.1`), pinned to transformers commit 50e35cc; **[E001]** = measured in this lab (`experiments/E001_arch/result.json`, `meta_analysis/PROCESS_LEDGER.md`); **[derived]** = my inference from the above, **not measured**; **[unverified]** = claim of a source not yet checked on the loaded model.

| id | fact | tag |
|---|---|---|
| K1 | 35 layers; KV sharing: layers 15–34 own no K/V projections and read K/V written by layer 13 (sliding layers) and layer 14 (full-attention layers; full layers are 4, 9, 14, 19, 24, 29, 34). Queries/o_proj stay per-layer. | [code] |
| K1′ | Consequence: a perturbation of the residual at any **non-final position at any layer ≥15 changes the final logits by exactly 0** (E001: 0 at layers 15, 16, 25, 34; 17.7–36.4 at layers 5, 13, 14). Residual-patching sweeps at non-final positions are only meaningful for layers ≤14; layers 15–34 only at the final position. Using this, `Runner(last_only_from=15)` is exact to 3.6e-5 and 2.16× faster (full 64.32 s vs 29.8 s). A resid_pre perturbation at layer 14 cannot change layer-13 K/V (only layer-14 K/V). | [code] + [E001]; the last sentence [derived] |
| K2 | Per-layer embeddings (PLE): token identity (lookup table of shape 262144 × 35·256) plus a projection of the input embeddings is injected additively into **every** layer; HF accepts `per_layer_inputs` only together with `inputs_embeds`, and the PLE lookup needs `input_ids`. Therefore residual-only patching/ablation at layer L leaves token identity re-available to layers >L, and **embedding-noise corruption perturbs only the projection part of PLE, not the lookup part**. | [code]; the consequence for patching/noise [derived] |
| K3 | Final logits = `30·tanh(logits/30)` (softcap 30) after the tied `lm_head`. tanh is monotone, so top-1/rank are preserved, but **logit differences and probabilities are not linear in pre-cap logits**. No attention-logit softcap in the text attention. | [code]; monotonicity consequence [derived] |
| K4 | Tied embeddings: `lm_head` shares `embed_tokens`; embedding output scaled by √1536. The PLE tables are separate. | [code] |
| K5 | RMSNorm without the Gemma 1–3 (1+w) offset; sandwich norms; learned `layer_scalar` multiplies the **whole residual stream** at the end of each layer (after PLE); post-layer residual = `model.language_model.layers[i]` output; the last `output_hidden_states` entry is post-final-norm, not resid_post[34]. | [code] |
| K6 | 8 query heads, **1 KV head** (every query head at a layer attends the same K/V), head_dim 256 (512 on full layers), `scaling=1.0`, q/k/v norms, sliding window 512 (4:1), p-RoPE (partial 0.25) on full layers. Window ≡ causal for prompts <512 tokens: to be verified. | [code]; window equivalence [unverified] |
| K7 | KV-shared layers 15–34 have double-wide MLPs (12288); E2B text decoder has no AltUp/LAuReL/MatFormer (those exist in Gemma 3n code). Checkpoint 10.25 GB bf16 including PLE table vs 8 GiB RAM. | [code] |
| K8 | Compute budget: 2 vCPU, 8 GiB, fp32 compute with bf16 storage; ~30–60 s per batched forward of ~300 tokens (e.g. 8×40) ≈ 5–10 tokens/s [derived arithmetic]. BOS must be prepended (`encode()`); chat template changes behaviour (LIT02-127: E2B-IT refused 65/75 prompts with template vs 0/75 without, authors report, abstract-level, single source). | [E001]/[ledger] + LIT02-127 |

Applicability legend: **OK** = usable as published; **MOD** = usable with the stated modification; **BLOCKED** = no validated tooling/weights; **UNKNOWN** = no evidence either way.
