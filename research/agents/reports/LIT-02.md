### 4.2 Methods table
| method | what it measures | known pitfalls | key refs |
|---|---|---|---|
| Activation patching, denoising (clean→corrupt) | sufficiency of a component for behaviour | corrupted-prompt choice changes what is traced; not minimal; OR-gates/backup behaviour hide components; off-distribution activations | LIT02-005, LIT02-004, LIT02-030, LIT02-014 |
| Noising (corrupt→clean) | necessity | asymmetric to denoising; self-repair masks effect | LIT02-005, LIT02-015 |
| Path / edge patching | effect of specific edges | combinatorial cost | LIT02-006, LIT02-009 |
| Attribution patching (AtP, EAP, AtP*) | first-order approximation of patch effect | false negatives from saturation; unreliability characterised in 2026 work | LIT02-132, LIT02-007, LIT02-008, LIT02-013 |
| Zero / mean / resample ablation, causal scrubbing | necessity/faithfulness of a circuit | faithfulness scores highly sensitive to ablation type, metric, positions; head-ablation implementation can change results (r=0.057 between two zeroing variants in GPT-2 small, authors report) | LIT02-022, LIT02-029, LIT02-133/134 |
| Causal mediation / causal abstraction / DAS | whether a hypothesised variable is causally implemented | subspace patching can use dormant pathways (illusion; disputed); expressive alignment maps trivialise abstraction | LIT02-016, LIT02-017, LIT02-018, LIT02-025 |
| Steering vectors (ActAdd, CAA, ITI, RepE) | whether a direction causally controls behaviour | per-example variance, sometimes reversed sign; success predicted by geometry; non-identifiability | LIT02-034, LIT02-036, LIT02-038, LIT02-039, LIT02-042 |
| Logit/tuned lens, Patchscopes, future lens | what intermediate states "predict" | readout ≠ computation (steerable-not-decodable); per-model translator training needed; lens tools assume standard final norm/unembed (Gemma uses logit soft-capping per docs snippet, to be verified) | LIT02-131, LIT02-047, LIT02-051, LIT02-055 |

## 8 Justified next actions — replication experiments feasible on Gemma 4 E2B (2 vCPU, 8 GiB, CPU-only)
Feasibility caveat (assumption): total parameters 5.1B with embeddings (model card) ≈ 10 GB in bf16, so loading needs mmap/lazy PLE tables or 8-bit weights; speed per forward is unmeasured. All protocols are forward-only, ≤ ~40-token prompts, batch 1–4. Record dtype (bf16 vs fp32 numerics can change patch effects), chat-template on/off (LIT02-127), seeds, tokenizer single-token checks. Pre-register predictions in each PREREG.md before running. Always report noising AND denoising, plus individual answer logprobs (LIT02-005).

**R1 — IOI-style indirect-object patching (cheapest, method-validation).** Data: templated sentences (ABBA/BABA, ~10 templates × ~40 single-token name pairs, 200 prompts; check Gemma tokenization gives single tokens). Corruption: symmetric token replacement (swap IO name to a third name; ABC) versus Gaussian-noise embedding corruption (LIT02-004). Metric: logit difference logit(IO)−logit(S), normalised (patched−corrupt)/(clean−corrupt), plus logprob of each. Units: residual stream per layer×position, attention head outputs (pre-o_proj; GQA with 1 KV head means K/V are shared, query heads differ — patch z before projection, cf. LIT02-029), MLP outputs. Baselines: 1,000 random same-size head sets; mean- and resample-ablation comparisons (LIT02-022); bootstrap CIs over prompts. Pass criterion fixed in advance: top-k components' recovery exceeds 95th percentile of random sets.
**R2 — Factual recall staging (LIT02-065, LIT02-002).** Data: ~150 (subject, relation, object) triples across ≥5 relations that the model answers correctly (filter on greedy answer). Corruption: same-relation different-subject counterfactual (also Gaussian-noise variant). Metric: logit difference of true vs counterfactual attribute. Interventions: patch MLP vs attention output at last-subject-token vs last position by layer; attention knockout of last-position→subject edges in sliding layer windows. Controls: random-window knockout, non-subject token patches. Prediction (pre-registered from literature): MLP effect at last-subject token in early/mid layers, attention extraction at last position in later layers; note local-window layers (512) are irrelevant for short prompts but KV-shared layers need source-layer patching.
**R3 — Logit vs tuned lens on Gemma 4 E2B (+ latent-language test).** Metric: KL(lens‖final) and top-1 agreement per layer on ~2k held-out tokens; tuned translators trained on a small corpus (note CPU limit; use a few hundred thousand tokens and report undertraining). Baselines: identity (logit lens), random-init translators. Apply final norm and soft-cap consistently. Application: fr→zh translation (Wendler protocol, LIT02-079) measuring English-token probability mass by layer, with control tasks to address the probe-artifact critique (LIT02-084).
**R4 — Steering-vector reliability (LIT02-038, LIT02-039).** Data: 200–300 A/B multiple-choice items for 2–3 behaviours from public datasets (sycophancy, corrigibility), held-out split for evaluation. Vector: mean activation difference at layer sweep. Metric: per-example change in logit difference of target answer (report distribution, fraction with reversed sign), not only the mean. Baselines: random vector of equal norm, label-shuffled difference vector. Pre-register predictors: directional agreement and separability (LIT02-039).
**R5 — Refusal direction (LIT02-088, tests LIT02-089).** Data: public harmful/harmless instruction sets (~100 each; use refusal-token log-odds and refusal-prefix match; do not generate or store harmful completions). Difference-in-means direction at a layer sweep; directional ablation and activation addition; compare with top-k (k=1..5) subspace. Baselines: random direction, shuffled-label direction. Report with and without chat template. 
**R6 — Induction heads (cheap sanity check).** Random-token sequences repeated once (length 25); induction score = loss(second repeat) vs loss(first); prefix-matching score per head; ablate top-k heads vs random-k heads and measure loss change; optional few-shot ICL accuracy drop (LIT02-058).
**R7 (lower priority) — behavioural CoT hint-injection (LIT02-096, LIT02-099).** ~100 MC questions with injected hint; metrics: answer-switch rate toward hint and verbalisation rate; small model may produce little reasoning, so treat as exploratory.
Order of execution by cost/value: R6 → R1 → R2 → R3 → R4 → R5 → R7. All runs need independent audit (code review + rerun with different seeds/prompt templates) before any status above SOURCE_SUPPORTED/EXPERIMENTALLY_SUPPORTED.
